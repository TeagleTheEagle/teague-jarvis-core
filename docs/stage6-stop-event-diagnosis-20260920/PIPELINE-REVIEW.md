# E2 review before diagnostic instrumentation

Original infrastructure: `../stage6-heartbeat-decoupled-20260918/`.

1. `monitor.ps1` registers WQL subscriptions for `Win32_ProcessStartTrace` and `Win32_ProcessStopTrace`, locally through Register-CimIndicationEvent. Filters match VBox*, VirtualBox*, J6Probe*. No Action handler, max-trigger limit, deduplication or identity-resolution lookup is configured.
2. Microsoft CIM cmdlet indication watcher raises its event; PowerShell creates a PSEventArgs and queues it in the local session's ReceivedEvents collection. This portion is not instrumented historically. SourceIdentifier distinguishes START from STOP. No creation identity is added at this stage.
3. `monitor.ps1::Drain` snapshots each subscription with Get-Event, validates NewEvent, serializes PID/name/native TIME_CREATED and queue TimeGenerated, uses AppendAllText(events.jsonl), increments persisted count, then Remove-Event by EventIdentifier. It queries final backlog. Wrong/duplicate event identifiers and notifications never enqueued were not independently observable in prior logs.
4. `campaign.py` launches J6Probe, retains Popen process handles, waits for exit, gets GetProcessTimes creation FILETIME, rejects duplicate PIDs and saves exit=0 evidence. Historical exit FILETIME is not saved.
5. The consumer finishes all phases/last health poll and writes collector-finished. Monitor checks this after a heartbeat, waits its existing two seconds, drains once, enumerates VBox processes, freezes collection, Flush(true), closes, saves monitor-result, then unsubscribes and removes remaining queued events in finally. This order has a possible unobserved interval between final drain and unsubscribe; it is not evidence that this caused the historical loss.
6. `finalize.py::finalize` requires monitor exit, healthy journal, exact 2N events, distinct probe PIDs and one START/STOP by PID/name. It rejects missing events before receipt/archive acceptance. The stop timestamp is not synthesized from process wait completion.

Diagnostic plan: copy monitor only into this new directory. Attach non-consuming C# observation handlers to the existing CIM watcher's public event and the PowerShell collection's PSEventReceived event. Record monotonic times and native event keys in bounded in-memory traces, plus EventIdentifier at queue/drain/serialization/write/removal boundaries. No Action script replacing the existing queue. Add a separate System.Management WMI observer of the same native source as a transport comparison, explicitly NOT an independent kernel provider. Retained process handles and GetProcessTimes exit FILETIME supply independent kernel lifecycle ground truth (not STOP notifications). If independent ETW is unavailable without extra installation/broad tracing, disclose that limitation rather than call the parallel WMI observer independent. Keep current grace, heartbeat threshold, queue semantics and final acceptance unchanged. Record queues before unsubscribe and any discarded events. No protected paths are used.

Two separate bounded campaigns will exercise all five classes, with C: reads receiving the longest exposure. Diagnostic probe rate may be higher than historical five-second rate; report it. Instrumentation perturbs timing, so failure to reproduce cannot exonerate the historical failure. No monitor correction or protected-baseline retry is authorized by this diagnosis.

Installed runtime reports 7.6.5; do not assume source-version identity. Verify hook behavior with a synthetic in-process smoke check.

Unobserved internals: native provider emission cannot be counted before arrival by these hooks; raw watcher tap follows existing handler registration and can run after an enqueue. Its timestamp is callback-tap observation, not a claim of first native callback entry. Trace this possible ordering rather than clamp negative inferred latency to zero.
