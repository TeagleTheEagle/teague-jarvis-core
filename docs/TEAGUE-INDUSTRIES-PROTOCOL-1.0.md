# TEAGUE INDUSTRIES — PROTOCOL 1.0

**Status:** UI rebranding and product-structure checkpoint  
**Scope:** Presentation, navigation, branding and prototype launcher only  
**Core rule:** Teague Industries is the ecosystem; JARVIS is the shared intelligence.

## Product model

### Previous presentation

The desktop shell presented itself primarily as **JARVIS**, with a Teague Suite popup containing prototype surfaces.

### Protocol 1.0 presentation

The desktop shell is now presented as:

**TEAGUE INDUSTRIES**  
**COMMAND CENTER**

JARVIS remains visible as the shared assistant and intelligence layer:

- `JARVIS ONLINE`
- `JARVIS CORE`
- `ONLINE · SHARED CORE`
- `POWERED BY JARVIS` where appropriate

The application launcher exposes prototype clients for JARVIS, Browser, Projects, Technology and System without creating separate assistants or production executables.

## Shared architecture preserved

The following remain authoritative and unchanged:

- one JARVIS Core
- one personality and context system
- one memory store
- one authorization system
- one capability registry
- existing provider routing
- existing voice, vision and Milestone 4 pipeline
- existing PC, phone and wearable adapters
- existing security boundaries

The Command Center is an interface around the existing runtime. JARVIS Core is not dependent on the UI process.

## UI changes in Protocol 1.0

- Updated the document title and desktop header to Teague Industries Command Center.
- Added `JARVIS · ONLINE · SHARED CORE` hierarchy to the shared header.
- Renamed the visible suite control to `APPLICATIONS`.
- Reframed the modal as the `TEAGUE INDUSTRIES / COMMAND CENTER` application launcher.
- Retained the five visual prototype surfaces and their shared JARVIS panel.
- Kept all prototype-only data clearly labelled as `PROTOTYPE`, `MOCK` or `UNAVAILABLE`.
- Retained the metallic/electric-blue Teague mark and existing JARVIS holographic visual language.

## Future applications

1. **JARVIS** — conversation, voice, vision, memory, hologram and direct AI interaction.
2. **TEAGUE INDUSTRIES BROWSER** — web research, sources, downloads and future Mail/Drive integrations.
3. **TEAGUE INDUSTRIES PROJECTS** — projects, goals, tasks, milestones, decisions and experiments.
4. **TEAGUE INDUSTRIES TECHNOLOGY** — hardware, devices, J1, glasses, telemetry and engineering evidence.
5. **TEAGUE INDUSTRIES SYSTEM** — Core health, providers, performance, security, permissions and logs.

These are specialized clients of one intelligence, not independent JARVIS instances.

## What remains prototype-only

- The application launcher is a UI surface inside the existing desktop shell.
- Browser Mail and Drive areas are mock interfaces.
- Cross-application handoff is a visual simulation.
- Device topology and System values are only live where the existing Core supplies evidence; other values are labelled mock or unavailable.
- No production Gateway or cross-process orchestration exists yet.
