# Proposed bounded final overhead screen — OWNER REVIEW ONLY

NOT EXECUTED. No authorization is inferred from the implementation gate. No live ETW or UAC is proposed here.

1. Freeze a separately reviewed same-input offline benchmark fixture, its source/binary/assembly identities, current successor/reference hashes and analysis contract before timing. Baseline A must reproduce the unchanged predecessor path without the newly added handoff initialization or stores; merely disabling the successor recorder is not an adequate total-instrumentation baseline. B is the fully instrumented separate-clock reference. C is the semantic timestamp-reuse successor. Compile with identical toolchain/options and preserve all three generated paths. If baseline equivalence cannot be shown, stop before measurement.
2. Use identical deterministic callback inputs and decision outcomes for all arms. Declare the exact source-derived branch mix before launch: admitted START, admitted STOP, unknown parent, unknown instance, duplicate START/STOP, invalid identity, decode failure, capacity rejection and handled exception, plus non-lifecycle control. Controlled dependency adapters remain identical and are explicitly reported; this does not qualify live ETW integration. Fix the input order and retain a digest. No artificial sleeps, work inflation or dynamic calibration.
3. Proposed fixed balanced schedule: ABC, BCA, CAB, ACB, CBA, BAC, repeated ten times = 60 complete blocks. This is balanced, not randomized. Each arm uses 20,000 excluded warm-up callbacks and 1,000,000 measured callbacks. Total measured callbacks 180,000,000; warm-up 3,600,000. Group ten consecutive blocks into six group means. No extension/retry/replacement/ordinary-noise exclusion. A single 1,200-second launcher limit applies; interruption or incomplete block invalidates the run.
4. Preserve recorder capacity. Exercise fixed, declared chunks of at most 8,192 callbacks; after each chunk and after callback return, digest the recorded output and reset only the offline fixture recorder between chunks. Exclude chunk digest/reset from measured thread-CPU intervals consistently. Do not introduce this reset into observer code. Record the fixed final partial-chunk size. Capacity/overflow are separately checked outside timing; a surprise overflow is failure, not an excuse to drop records.
5. Primary metric: callback-thread CPU ns/callback, including all handoff stores and instrumentation. Retain raw CPU counters, QPC wall intervals, throughput, counts, identities and order. Use the predeclared within-block percentages C/A-1 (final overhead), B/A-1 (reference overhead), and B-C (reuse benefit). Use Student-t 95% intervals across the six grouped means. Do not change estimator after seeing results.
6. Final <=1.0% screen PASS requires C/A-1 interval upper bound <=1.0%, all input/output/semantic validations passing, and no material drift/dependence undermining inference. If the lower bound is >1.0%, overhead fails. Otherwise the screen is inconclusive. B-C does not substitute for C-A and cannot qualify the <=1% requirement. The fixed sample may be insufficient; no extension is allowed.
7. Predeclare drift diagnostics by block position, treatment position and grouped residuals. Preserve all results. If inference is invalid or causes remain unresolved, report that; do not select another estimator. Historical profiling is comparison only, never pooled.
8. After the one run: verify all frozen hashes, zero matching processes/trace sessions, archive all raw and derived evidence and hash-verify it. Stop for owner review. No medium/large run, observer integration, protected VM access or production operation follows automatically.

The executable/command must be bound after the separately reviewed three-arm fixture exists; there is intentionally no runnable command against the present two-arm semantic-test binary. Running it as a benchmark now would not implement this protocol.
